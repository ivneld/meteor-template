# 플레이북: 규칙을 지킬 수 없을 때

규칙을 지키면 요구사항을 만족할 수 없어 보일 때. 에이전트는 규칙을 우회하는 코드를 쓰지 않는다.

## 에이전트가 할 일

1. 먼저 다른 모양을 찾는다. 대부분은 코드 위치를 바꾸면 해결된다.
   - 다른 애그리거트가 필요하다 → usecase 에서 엮는다(R-04).
   - 판단이 저장소 조회를 필요로 한다 → 사실을 꺼내 `*Policy` 에 넘긴다(S-04).
   - 컨트롤러에서 여러 개를 불러야 한다 → usecase 메서드 하나로(R-11).
2. 그래도 안 되면 멈추고 사람에게 묻는다. 어떤 규칙(ID)이 무엇을 막는지, 시도한 대안, 예외가 필요한 이유를 적는다.
3. 사람이 예외를 승인하면 아래 절차를 따른다. 승인 없이 ArchUnit 규칙이나 동결 파일을 고치지 않는다.

## 예외 절차 (사람이 승인한 뒤)

1. ArchUnit 위반이면 `FreezingArchRule` 로 그 위반만 동결하고 동결 파일을 커밋한다.
2. `docs/adr/NNNN-<제목>.md` 에 ADR 을 쓴다: 규칙 ID, 이유, 만료 조건(날짜 또는 상황), 되돌리는 방법.
3. 리뷰 에이전트(S 규칙) 지적이면 리뷰 요청에 ADR 링크를 적는다.

## 규칙 자체를 바꿔야 할 때

규칙 변경은 한 PR 에서 함께 한다: `ArchitectureRules`(구조 규칙) 또는 리뷰 프롬프트, `harness/rules/<ID>-*.md`, `docs/architecture/` 의 해당 장과 `rules.md`, `AGENTS.md` 의 규칙 표. `RuleCatalogTest` 가 ID 가 어긋나면 실패한다. 없앤 번호는 다시 쓰지 않는다.
