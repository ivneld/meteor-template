# 아키텍처

분리형 템플릿의 아키텍처 문서다. 애그리거트와 JPA 엔티티를 다른 타입으로 두고, 규칙은 도메인 모델 한 곳에, 트랜잭션 경계는 코드에 보이게
둔다. 코드는 `domain`, `usecase`, `api` 세 계층으로만 나눈다.

## 한 장 요약

```
 api ──────────► usecase ──────────► domain ──────► storage
  │                 │                  ▲  (*Repository 만)
  │                 └──► clients       │
  └────────────────────────────────────┘
     (애그리거트 하나로 끝나는 흐름은 api 가 *Reader / *Writer 를 바로 부른다)
```

| 원칙 | 한 줄 |
|---|---|
| 1. 계층은 셋 | domain / usecase / api. 커지면 그때 나눈다 |
| 2. 규칙은 도메인 모델에 | 애그리거트와 `*Policy` 만 판단한다 |
| 3. 도메인 서비스는 애그리거트 하나 | `*Reader` / `*Writer` 는 자기 `*Repository` 만, 엮는 일은 usecase |
| 4. 트랜잭션 경계가 보인다 | 도메인 서비스는 기본 전파, 경계 조절은 usecase 만 |
| 5. 엔티티와 애그리거트를 분리 | JPA 는 영속 엔진으로만, 변환은 `*Repository` 어댑터 안에서 |
| 6. API 계약은 따로 | 요청·응답에 도메인 타입을 쓰지 않는다 |
| 7. 지금 이득인 대비만 | 미래용 장치는 두지 않는다 |
